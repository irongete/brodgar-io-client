- 031-window-lifecycle — ACTIVE — feature **B3a**: a hidden native window stops coming back. `MenuCheckBox.setgkey` means the key and the menu button fire the SAME click, so both land in the private `GameUI.togglewnd` (:1481), which flips `visible` on the very window the addon hid — seven call sites, ONE method, its tick read by the private `wndstate` (:1475). Model from 029: **a native window you hid is a window you own** (`Addon.hiddenNative` is already the record). `w:hide()` ⇒ the toggle is swallowed; `replace` ⇒ the toggle drives your view and `wndstate` reads it. **No new public API** — `replace` knows both halves, and the view IS the state (no bookkeeping boolean). **One teardown rule: the window ends up as the user was seeing it** (view open ⇒ stock open; nothing on screen ⇒ closed — the wrapper is hidden by default, so a blind `show()` gets it wrong). Core edit = two `// addon:` one-liners inside the method bodies, no visibility change (design/07,08) — tasks 031.1..031.3
- 030-ui-selectors — DONE — feature **B2**: one way to point at a part of the UI. `hafen.ui` is CALLABLE (D-056) — `hafen.ui(sel)` the first match in tree order / `hafen.ui.all(sel)` every match (empty array, never nil) / `hafen.ui()` the root, `hafen.ui.root()` hard-cut; grammar `*` · role · `@Class` · `[title=]` · `[res=]`, parsed ONCE into a predicate over one widget, no descendant selectors. Roles reuse `Fonts.SCOPES` but not 1:1 (`"default"` → `*`, 10 carry over, `window` + `inventory` are new) and the scopes gave only the NAMES: the widget→role **classifier** (`LuaWidget.role`, one `instanceof` chain) is the heart of the feature, and **D-067** is what it taught — five promoted names classify NOTHING because they name a render *site*, not a widget, and guessing is worse than `nil` (174 of 625 widgets classify on a live HUD; `all("*")` = 0.08 ms). `[title=]` resolves against the nearest enclosing `Window` (a bare `Inventory` has no `cap`) and `@Class` is an exact `typeName`, no superclass walk. `hafen.ui.on(sel, "appear"|"disappear", fn)` **hard-cuts `onWidgetCreate`** and hands back the Widget entity: registration SCANS the live tree (**D-068** — "appear" is a state, not an edge, so a `:reload` no longer loses every open window), while `disappear` fires when a widget stops being **real**, not drawn (a closing `Window` lingers, readable, for its fade-out); cost scales with widget creation, not frames, via a structural/refiner split + a bounded 20-tick re-check for late captions. The spec's `[res=]`-for-windows promise was **refuted in-game** (no window here carries a resource; 69 of 625 widgets do) and the docs say so. The **inspector ships inside the feature**, in `widgetstack`: hover → role/class/title/res + every selector it has already RESOLVED, most specific first, in the honest form. `replace(selector)` deferred to B3 on semantics, not size. **Zero core edits** (design/20,21,08 → the standing `design/22-ui-selectors.md`) — tasks 030.1..030.4
- 029-widget-oop — DONE — feature **B1**: the three objects `hafen.ui` returned for one widget (window/widget handle · `adopt`/`replace` model · transient `WidgetNode`) collapsed into ONE interned entity — what you create and what you find are the same type, `:info()` the snapshot hatch, `==` the identity test (`:same()` cut). Reading stopped being coupled to replacing: `widget:items()` answers on ANY container with its window **visible and interactive** (proved on a Cupboard, a Belt, the study and three chests no adapter had ever been written for), and the lifecycle moved onto the entity (`:onItemAdded/:onItemRemoved/:onDestroy`, a per-tick `WItem` diff whose **subscription IS the registration**). Items are a relation, so **`hafen.items` is hard-cut** (`hafen.ui.inventory()/equipment()` are widget lookups, `hand()` stays a snapshot, `find()` got no replacement); geometry is arity-as-verb (`:pos()`/`:pos(x,y)`) so `:move()` is cut, and the write verbs are OWNED-only with two distinct refusals while a write on a stale widget is a silent chaining no-op. **`adopt` is deleted, not renamed** — its whole job was a readable handle, so what remains is `w:hide()` + the restore list; `replace` is untouched (it hides the enclosing WINDOW and replays the captured visibility). The intern cache is weak on **both** axes (`WeakHashMap<Widget, WeakReference<LuaValue>>`, D-064) to keep D-041's no-pin rule, and the gating measurement came out backwards: interning is **~19x cheaper** than the closure-table handles it replaced (513 ns → 27 ns per node). Provenance is DERIVED from the tree, never stored (D-065); a thing inside another is a relation, not a section (D-066). Closed the `LuaModel`/`LuaMesh` collision 028 deferred by deletion; **zero core edits** across the whole feature (design/07,08,20) — tasks 029.1..029.4
