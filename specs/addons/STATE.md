**`031-window-lifecycle` DONE — feature B3a: a hidden native window stops coming back.** Observed with `bags`: the custom inventory **coexisted** with the stock one — Tab opened the client's too. The cause was never in `bags`: `MenuCheckBox` calls `setgkey`, so **the key and the menu button fire the SAME click**, and both land in the private `GameUI.togglewnd` (:1482), which flipped `visible` back on the very window the addon hid — **an addon's hide was a suggestion the client overruled one keypress later**. Seven call sites, **one private method**, its tick read by the private `wndstate` (:1475). **D-069**: hiding a native window **takes its toggle**, and 029's `Addon.hiddenNative` IS the ownership record — no new list, no new state, **no verb** (nothing to register, nothing to release; the same restore that gives the widget back gives the toggle back). The whole core edit is the promised **two `// addon:` one-liners INSIDE the two method bodies**, no visibility change and no new call site — the seam is `AddonWidgets.toggleWnd/wndState` → `AddonManager` → `UiApi`, so `haven` keeps one file that knows the addon layer exists. Ownership is matched by **widget identity against the CURRENT owners only** (`AddonManager.addons` + the `:lua` REPL), which covers every staleness case at once — a disabled addon, a relog, 030's fading corpse — so no per-frame liveness test is paid and a stale owner falls through to stock (a dead Tab is worse than a stock Tab). The frame path (`ACheckBox.state` is a per-draw `Supplier<Boolean>` on six checkboxes) **allocates nothing**: one volatile `LuaWidget.anyHidden` read when nothing is hidden, indexed loops otherwise. With nothing standing in for the window the toggle is **swallowed** and the tick answers `false`; with a view bound, `toggleWnd` does `show(!visible())` + raise/fit/focus and `wndState` answers **`view.visible()`** — no bookkeeping boolean, so the menu tick cannot drift from the screen. **`replace` wires itself** (031.2): it joins the one `Addon.hiddenNative` record `w:hide()` makes and binds its view to it — one record per window, `LuaModel` three fields lighter — because it is the only place that knows both halves. **D-070 is what the feature actually settled**: *a restore replays what the user was SEEING, not what the widget was*. `Hidden.origVisible` is **DELETED**; teardown, `:remove()` and a server destroy all restore as `view != null && view.visible()`, one rule with no branches — an addon whose custom inventory is open, then disabled, must leave the **stock** one open even though the wrapper it hid was hidden at the time. The two agree on the canonical unbound case, which is exactly why the old record *looked* right — **a remembered state that agrees with a derived one on every tested case is not evidence the state is needed**. Shipped behaviour change: a *bare* `w:hide()` on something that WAS visible now stays hidden through a `:reload` (correct — nothing stood in for it — and recoverable, since the toggle comes back with it). **One window, one owner** falls out of the same place: `w:hide()` on an already-owned native widget **throws** naming the first addon, `replace` **logs and skips** (the placement path must not throw into the engine). **Ordering became load-bearing**: `teardownHidden` runs **BEFORE** `destroyWidgets` — the rule reads the view's visibility and a destroyed view stands for nothing, a failure that would have been silent and always in the plausible direction. `fitwdg` is **re-derived, not exposed** (`UiApi.fitView`, over the view's own parent — the more correct frame), and the identity the seam rests on is **asserted, not assumed** (`assertToggleTarget`). **031.3 closed it, docs + Lua only:** `api/ui.md` needed no new section (031.1/031.2 each landed theirs as they shipped) — the close was the sweep plus two clauses, `replace`'s log-and-skip refusal and **what you own is what you point at** (hiding the grid leaves its window's key stock, which is what `hello`'s own `bags` hotkey does); `getting-started.md` gained the paragraph; the link/anchor checker over `docs/addons/` reports **0 broken over 551 links**. `bags` **v0.2.0** **KEEPS its hotkey with a changed meaning** — it ARMS and DISARMS the replacement, since Tab is the show/hide key now and nothing else can start or stop a replacement (the plan's "it may now drop it" was the right question with the opposite answer); its X restores an **open** stock window, because `reqclose` fires `onClose` before the view is killed. `hello` **v0.66.0** gained `readToggle(tag)` (login, +3s, `:hello wnd`): the swallow, the same-owner idempotence, the foreign-owner refusal **as the check's gate**, and **both halves of the teardown rule driven from Lua** through two live `replace` + `handle:remove()` rounds — then it restores the HUD **with the rule under test**. What Lua cannot do is press a key, so `:hello wnd swallow` **parks** the swallowed state for a human. Pre-checked headlessly by slicing `readToggle` out of the live `main.lua` and dry-running it under the LuaJ jar against a stub that models the engine's *rules* (5 scenarios / 18 checks), which caught a real bug: `(cond ~= nil) and w:visible() or nil` collapses a `false` to `nil`. Coverage paid across the feature: the new **`specs/codebase/gameui-windows.md`** (the toggle path, `Window`'s anim state machine — **`visible()` is animation-aware, so a fading-out window already reads false**, which is what lets a per-frame tick read a view directly — `GameUI.fitwdg`, and the correction that `show(boolean)` returns its own argument, not "did it change").

**`030-ui-selectors` DONE — feature B2: one way to point at a part of the UI.** `hafen.ui` is **callable** (D-056): `hafen.ui(sel)` = the first match in tree order, `hafen.ui.all(sel)` = every match (empty array, never nil), `hafen.ui()` = the root — **`hafen.ui.root()` hard cut**. The grammar is tiny and CSS-shaped, parsed **once** into a predicate over one widget, no descendant selectors: `*` · role · `@Class` · `[title=]` · `[res=]`, refiners in any order and at most once. **The classifier is the heart** (`LuaWidget.role`, ONE `instanceof` chain) and **D-067** is what it taught: a role is claimed only where the class genuinely IS that thing, so the five promoted `Fonts.SCOPES` names that name a *render site* — `window.title`/`heading`/`tooltip`/`world.nick`/`world.speech` — stay valid grammar and classify **nothing**. Measured on a live HUD: **174 of 625 widgets classify**, `all("*")` = **0.08 ms / 625 widgets** — hence the docs rule *hold your result* (free, since entities are interned). Two rules settled inside the matcher: **`[title=]` resolves against the nearest enclosing `Window`** (the widget's own caption would make the most obvious selector anyone writes silently never match), and **`@Class` is an exact `typeName`**, no superclass walk (anonymous subclasses are the norm). **The spec's `[res=]` promise was refuted in-game**: NO window on this server carries a resource (69 of 625 widgets do — items, the 3 `IMeter`s, the chat channels whose code ships inside a res), so `[title=]` is the only key for windows; **`:res()` was NOT in the plan** and had to be added. **`hafen.ui.on(sel, "appear"|"disappear", fn)`** hangs off the `onWidgetPlaced` seam and hands back the **Widget entity**; **`hafen.ui.onWidgetCreate` and `LuaWidgetObserver` are DELETED** (the descriptor survives ONLY as `replace{match=fn}`'s argument, which matches against the SERVER parent). **D-068**: registration **scans the live tree** and fires `appear` for what is already open — "appear" means *is in the tree as of now*, a state reached either way, not an edge — which is why every `:reload` used to lose every open window; **`disappear` fires when a widget stops being *real*, not *drawn*** (a closing window lingers, unbound and fully readable, for its whole fade-out), so at `disappear` the entity is a **key to match**, never a last chance to read. Cost scales with widget **creation**: `Selector` splits into `matchesStructure` + refiners, so only a `[title=]`/`[res=]` selector queues a `PendingMatch`, re-checked **20 ticks** (`-Dhaven.addon.selrecheck=`). **The inspector ships inside the feature**, in `widgetstack` **v0.4.0**: hovering turns into role (or an honest `nil`) · class · `[title=]` · `[res=]`, then **every selector built from those parts that actually matches**, most specific first, each with its match count and this widget's index — **the list is SELF-VALIDATING** (a candidate survives only after `hafen.ui.all()` resolved it and found the widget inside), which forces the honest form (`hafen.ui("…")` only when it is the FIRST match). Its in-game surprise: **hovering a window's frame never gives you the window** — the chrome is a CHILD (`@DefaultDeco`, role `nil`); `[title=]` still resolves *through* it. **Zero core edits in the whole feature.**

**`029-widget-oop` DONE — feature B1: the THREE objects `hafen.ui` handed back for one widget are ONE interned entity**; **what you create and what you find are the same type**, `:info()` the snapshot hatch. The consequence that mattered: **reading stopped being coupled to replacing** — `widget:items()` answers on ANY container with its window **visible and interactive**, where the only previous door was `hafen.ui.adopt(id)`, which HID the native window. The intern cache is `WeakHashMap<Widget, WeakReference<LuaValue>>`, weak on BOTH axes (**D-064**), because a strong-keyed map over a whole tree would pin every destroyed widget and break D-041. **The measurement gate passed the wrong way round**: the OLD `nodeHandle` cost **513 ns** per node (a `LuaTable` + fifteen closures), an interned hit **27 ns** — interning is ~19x **cheaper** than the handles it replaced. Creation doors intern on the **ROOT** (`content != root` is the whole "is this a window?" test); geometry is **arity-as-verb** (`:move()` HARD CUT); **provenance (OWNED vs BORROWED) is DERIVED from the tree, never stored (D-065)**, with two distinct refusals and a write on a STALE widget a **silent chaining no-op**. **`adopt` is DELETED** (its whole job was a readable handle); what remains is `w:hide()` and its restore record. Items are a **relation** on their container (**D-066**), so `hafen.items` is a HARD CUT, `inventory()`/`equipment()` are widget LOOKUPS and `hand()` stays a snapshot; the lifecycle (`:onItemAdded/:onItemRemoved/:onDestroy`, a per-tick `WItem` diff) is **hasSub-gated by construction** — the subscription IS the registration. That is what let `replace`'s bespoke model handle be deleted: `fn(model)` receives the ENTITY. 029.1 also established that a real `haven.UI` **can** be built off-screen (recorded in `specs/codebase/boot-and-loop.md`). **Zero core edits in the whole feature.**

## Engine & runtime
- **Engine**: LuaJ embedded (`src/io/brodgar/addon/`); per-addon sandboxed envs (D-017), instruction watchdog + soft per-tick CPU budget with auto-disable (D-018). **Loading/lifecycle**: `manifest.json` discovery from `addons/`; `:reload` rebuilds the addon layer only (D-005); enabled set persisted (D-006). Console `:lua` / `:addons` / `:reload`; AddOns panel (toggle/status).
- **Event bus** `hafen.events.on` (OnLoad/OnEnterWorld/OnUpdate/OnDisable, GobAdded/Removed (a Gob), MeterAdded/Removed/Changed (a Meter), Buff*/Fep/Study/Actionbar/Equip Changed, GhostClicked, ChatMessage…) — error-isolated, UI-thread-marshalled; timers `hafen.timer.after/every`. Container item events are **not** on the bus — they are per-widget (`w:onItemAdded/:onItemRemoved/:onDestroy`, 029.3). **Store**: `hafen.store` JSON saved-vars, per-char + account (D-023).
