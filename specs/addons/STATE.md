**`030-ui-selectors` DONE — feature B2: one way to point at a part of the UI.** `hafen.ui` is **callable** (D-056): `hafen.ui(sel)` = the first match in tree order, `hafen.ui.all(sel)` = every match (empty array, never nil), `hafen.ui()` = the root — **`hafen.ui.root()` hard cut**. The grammar is tiny and CSS-shaped, parsed **once** into a predicate over one widget, no descendant selectors: `*` · role · `@Class` · `[title=]` · `[res=]`, refiners in any order and at most once. **The classifier is the heart** (`LuaWidget.role`, ONE `instanceof` chain) and **D-067** is what it taught: a role is claimed only where the class genuinely IS that thing, so the five promoted `Fonts.SCOPES` names that name a *render site* — `window.title`/`heading`/`tooltip`/`world.nick`/`world.speech` — stay valid grammar and classify **nothing**. Measured on a live HUD: **174 of 625 widgets classify**, `all("*")` = **0.08 ms / 625 widgets** — hence the docs rule *hold your result* (free, since entities are interned). Two rules settled inside the matcher: **`[title=]` resolves against the nearest enclosing `Window`** (the widget's own caption would make the most obvious selector anyone writes silently never match), and **`@Class` is an exact `typeName`**, no superclass walk (anonymous subclasses are the norm). **The spec's `[res=]` promise was refuted in-game**: NO window on this server carries a resource (69 of 625 widgets do — items, the 3 `IMeter`s, the chat channels whose code ships inside a res), so `[title=]` is the only key for windows; **`:res()` was NOT in the plan** and had to be added. **`hafen.ui.on(sel, "appear"|"disappear", fn)`** hangs off the `onWidgetPlaced` seam and hands back the **Widget entity**; **`hafen.ui.onWidgetCreate` and `LuaWidgetObserver` are DELETED** (the descriptor survives ONLY as `replace{match=fn}`'s argument, which matches against the SERVER parent). **D-068**: registration **scans the live tree** and fires `appear` for what is already open — "appear" means *is in the tree as of now*, a state reached either way, not an edge — which is why every `:reload` used to lose every open window; **`disappear` fires when a widget stops being *real*, not *drawn*** (a closing window lingers, unbound and fully readable, for its whole fade-out), so at `disappear` the entity is a **key to match**, never a last chance to read. Cost scales with widget **creation**: `Selector` splits into `matchesStructure` + refiners, so only a `[title=]`/`[res=]` selector queues a `PendingMatch`, re-checked **20 ticks** (`-Dhaven.addon.selrecheck=`). **The inspector ships inside the feature**, in `widgetstack` **v0.4.0**: hovering turns into role (or an honest `nil`) · class · `[title=]` · `[res=]`, then **every selector built from those parts that actually matches**, most specific first, each with its match count and this widget's index — **the list is SELF-VALIDATING** (a candidate survives only after `hafen.ui.all()` resolved it and found the widget inside), which forces the honest form (`hafen.ui("…")` only when it is the FIRST match). **`029-widget-oop` DONE — feature B1: the THREE objects `hafen.ui` handed back for one widget are ONE interned entity**; **what you create and what you find are the same type**, `:info()` the snapshot hatch.
