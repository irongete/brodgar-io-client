**050.1 DONE, 4/4 + 4 manual**: the engine half. `Permission` is 22 entries carrying key · Lua spelling · plain line, so the gate's refusal, the manifest validator, the `:lua` owner and the dialog read ONE list; `PermissionSet` parses an exact key or a `<prefix>.*` group **matched on dot segments** (**D-228**), throws at load on anything else listing the whole vocabulary, and gives the bare `"*"` no spelling at all — the REPL owner is built from `values()`. The persisted pref stopped recording THAT the user was asked and records **WHAT they consented to** (**D-229**), the policy being one containment test: *declared ⊆ consented* → their choice stands, else disable and ask again; declaring nothing is never touched, asking for less never re-prompts. That makes every non-dialog path fail-closed by construction, so the console's `:addons enable` now says it cannot grant instead of letting the next `:reload` look broken. The suite **declares a deliberate subset** and is proven by both halves at once: 5 declared verbs reaching their own ARGUMENT refusal (D-213 — the gate is first, so getting there IS the grant) and 17 refusing by name, with the sharp case being that the exact `player.move` does **not** leak into the nested `player.hand.use`. Three verbs need world state a suite may not create (a held item, an open recipe, an Item), so they are counted and reported as a `[manual]` re-run rather than a `[fail]`. The maintainer's run found the last defect: a row whose *manifest* failed kept a ticked checkbox and read "not loaded", because `liveStatus` is I/O-free by design and `describeAddons` was discarding the parser's message — the panel now carries the reason and renders that row unticked and inert.

**[`049-css-selectors`](049-css-selectors/) is CLOSED, 5 of 5** — the selector grammar is **real CSS**, so ONE string names ONE nested widget (`window[title=Cupboard] button[text=Close]`) instead of `all(sel)[i]` with a **positional index** that silently meant a different widget the moment a second matching window opened. The space is the **descendant combinator**, which is what let the ancestor test move out of `[title=]` so every attribute tests the widget its own step is written on. Reverses design/22's "no descendant selectors, no operators" scope line.
**049.5 DONE, 13/13**: the docs tier. 049.1/049.2/049.4 each shipped their own pages the day they landed — a shipped page teaching a selector that ERRORS could not wait four tasks — so what the closing pass actually found was in the pages the feature never opened, and all three were **boundary lists written in the negative**, invisible to any grep aimed at the new syntax: `guides/theming.md` and `ui/style/README.md` still promised *no descendant selectors*, the latter also *no specificity arithmetic beyond the four parts* (a chain sums over them), and `guides/debugging.md` knew only "matches nothing" where `find` now RAISES on two or more. The suite's own claim — the reference teaches no selector that errors — is an assertion, not a proofread: 38 quoted strings, driven through `:all` (which raises for exactly one reason, a parse error, where `find` also raises on an ambiguous but legal one), sliced by banner comments and pre-checked against the REAL `Selector.parse` before the client starts. §12: 1537 links / 0 broken falsified four ways, 184 `Retired.java` rows re-derived with every grep at 0 and seven plants caught, 301 colon verbs with 7 accounted for.
**049.4 DONE, 13/13 + 1 manual**: the inspector's bug was worse than "does not build chains". `widgetstack` resolves every candidate through `:all()` and **pcall-drops what fails**, so it could not tell a miss from a **parse error** — since 049.1 every candidate it built for a widget inside a titled window raised and vanished, and the panel quietly stopped offering its best line with no error anywhere. `windowTitle` is deleted; the enclosing window is an `anchorStep` (nearest **strictly** enclosing captioned one) and the target step carries the widget's OWN `[title=]`/`[text=]` **by role**. Enumeration became **mixed-radix over grammar KEYS** rather than a bitmask over parts (two forms of one key cannot co-occur), and the **role is required** wherever there is one — `@Label` and `label@Label` match the identical set, so a role-less twin is only a vaguer spelling, and requiring it is what makes `[title=]` legal at all. The offer is the most specific candidate naming the widget **ALONE**, which is the only thing that lets a `find(...)` line be offered; the operators are offered where they say what `=` cannot (`[res*=<last segment>]`, `[text^=<stem before the first digit>]`), and the header reports the walk count and how many were chains. Some widgets simply cannot be named alone (nine identical Character Sheet rows) and the panel says so with an index instead of inventing a key.
**049.3 DONE, 14/14**: the two consumers that CACHE an answer — the `appear`/`disappear` subscriptions and the stylesheet's tree keys — needed nothing widened (049.1's `walk` already covers `matchesStructure`/`late()`; `bare()` already makes every chain a tree key). What was missing sat behind both: **the seam that said a caption moved carried no widget**, which is fine while `[title=]` decides only the window holding it and useless once it sits on an *ancestor* step. It moved to `Window.chcap` — the one post-construction write — and hands over the WINDOW (**D-227**), so both caches act on its **SUBTREE**: `appear` re-offers every widget below it, the sheet drops every cached style below it. Three things fell out: the reverse direction the sheet never saw (a rule that WAS matching and should stop — a settled negative was only half the bug), an addon's own `w:title(s)` now announcing like the server's `uimsg` does, and the whole mechanism becoming provable without the server (8/8 headless, negative control included — a suite must **settle** the negative past `styleOf`'s re-fold countdown or it asserts the countdown, not the seam). `pending` stays for `[res=]`, which resolves with no moment of its own; both paths end in one `offer()`, so a match fires exactly once. The layout half kept the old argument-less contract and is [in ROADMAP.md](ROADMAP.md).
**049.2 DONE, 11/11**: `find` **refuses** two matches rather than handing back the first (**D-224**) — the classifier's *never a wrong answer in place of no answer* reaching the lookup beside it, sayable only because 049.1's chain gave an author a way to name the one they mean. It walks the WHOLE tree (`firstMatch` deleted: a strict singular lookup has no fast path), and `one()` is the shared nil/one/raise split whose message quotes the caller's own door. `w:find`/`w:all` search one subtree, inclusive: the scope narrows the **candidates**, never the selector, so an ancestor step still names a widget above it (**D-225**, CSS `querySelector`), and a **departed** subject REFUSES at both doors where every other read answers nil/empty (**D-226**) — "no match" and "it is gone" are different facts. Nothing warns about the change, so the audit was by hand: frozen `hello` had five raising `find`s (its own `appear` callback among them, now `w:find("inventory")`), `theme` looked windows up by a key read from a FILE, and `widgetstack` offered a paste line for the FIRST of several.
**049.1 DONE, 17/17**: `Selector` is a `Step[]` matched **greedy right-to-left** with no backtracking — sound only while every combinator is descendant (**D-221**), which is what let the ancestor test move OUT of `[title=]` (`windowTitle` deleted) so every attribute tests its own step's widget. The old spelling would still have PARSED and merely never matched, so it is refused at **parse time** naming its replacement (**D-222**); the one migration a runtime cannot catch is `[res=]`, exact now where it was an implicit substring, joined by `*=`/`^=`/`$=`. The two keys are disjoint at **BOTH** ends (**D-223**) — a grammar rule alone left `*[text=Cupboard]` matching a window, since the text reader answers `Window.cap`. The split ignores whitespace **inside** brackets (shipped `theme` carries `window[title=Character Sheet]`), and `Sheet` stopped reading `Selector`'s fields.

## Engine & runtime
- **Engine**: LuaJ embedded (`src/io/brodgar/addon/`); per-addon sandboxed envs (D-017), instruction watchdog + soft per-tick CPU budget with auto-disable (D-018). **Loading/lifecycle**: `manifest.json` discovery from `addons/`; `:reload` rebuilds the addon layer only (D-005); enabled set persisted (D-006). Console `:lua` / `:addons` / `:reload`; AddOns panel (toggle/status, and the manifest `description` as the row's tooltip). **Event bus** `hafen.event():on` (Load/EnterWorld/Update/Disable, GobAdded/Removed (a Gob), MeterAdded/Removed/Changed (a Meter), Buff*/Fep/Study/Actionbar/Equip/Markers Changed, FlowerMenuOpened/Closed, GhostClicked…) — error-isolated, UI-thread-marshalled; timers `hafen.timer():after/:every`. Container item events are **not** on the bus — they are per-widget (`w:on("ItemAdded"/"ItemRemoved"/"Destroy", fn)`). **Store**: `hafen.store():get(name)` JSON saved-vars, per-char + account (D-023), handing back the LIVE table.

## The `hafen.*` surface — the docs tier IS the contract

- **One grammar** (039 §2 · `docs/addons/api/conventions.md`): a section is CALLED and is a per-addon singleton, everything after it is a colon verb, **arity is the verb**, a set is a **collection**, every read hands back a live interned object with `:info()` as the only snapshot, an explicit `nil` raises except where a page documents a meaning for it, a builder is constructed bare and configured by chained setters, a place is a **Position**, and every retired spelling **throws naming its replacement**. Every notification is `X:on(key, fn)` → a `Sub`, `sub:off()` ends it (041); the per-verb surface is `docs/addons/api/` and is deliberately not copied here.
- **Protected tier** (*gated* retired with 048, D-215; the manifest permission is still `"actions"`): the write verbs, behind the per-addon `actions` permission with enable-time consent and no global switch (D-027/D-028); `hafen.http` carries its own `network` host allowlist. Each verb is documented on the page of what it changes, under a `Write (protected: actions)` heading. Everything else observes, or writes client-local only and says `(unprotected)` on its page.
- **Example addons** (14, installed, dormant until asked): frozen `hello`, `bags`, `theme`, `atlas`, `stockfilter`, `planner`, `cupboard`, `tagger`, `widgetstack`, `profiler`, `optionstest`, `walker`, `netdemo`, `hogtest` — each described in `docs/addons/examples.md`, each carrying one accurate paragraph in its manifest (D-142).
- **Testing**: one self-checking suite per task, run by hand as `:t<NNN>-<X>` (`specs/addons/TESTING.md`). Lives in `addons/<NNN>-<feature>.<X>/` while in flight; `/end` archives it to `specs/addons/<NNN>-<feature>/addons/<NNN>-<feature>.<X>/` once closed (D-183), so only the example addons and frozen `hello` stay loaded at login. The regression is never run in practice — each task's own suite carries forward whatever it depends on (`TESTING.md`).
