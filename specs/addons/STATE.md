# STATE — what works right now

> Maintained by REPLACING (max 60 lines). Branch `feature/addons`; per-feature detail: its `NNN-` folder.

**`030-ui-selectors` DONE — feature B2: one way to point at a part of the UI.** 029 gave `hafen.ui` ONE entity; 030 gives it the vocabulary to **name** one. `hafen.ui` is **callable** (D-056): `hafen.ui(sel)` = the first match in tree order, `hafen.ui.all(sel)` = every match (empty array, never nil), `hafen.ui()` = the root — **`hafen.ui.root()` hard cut**. The grammar is tiny and CSS-shaped, parsed **once** into a predicate over one widget, no descendant selectors: `*` · role · `@Class` · `[title=]` · `[res=]`, refiners in any order and at most once. **The classifier is the heart** (`LuaWidget.role`, ONE `instanceof` chain) and **D-067** is what it taught: a role is claimed only where the class genuinely IS that thing, so the five promoted `Fonts.SCOPES` names that name a *render site* — `window.title`/`heading`/`tooltip`/`world.nick`/`world.speech` — stay valid grammar and classify **nothing**, because guessing a `Label` is a `heading` is exactly the wrong answer. Measured on a live HUD: **174 of 625 widgets classify**, and **`all("*")` = 0.08 ms / 625 widgets** — once-per-event cheap, per-frame expensive, hence the docs rule *hold your result* (free, since entities are interned). Two rules settled inside the matcher: **`[title=]` resolves against the nearest enclosing `Window`** (`window[title=Cupboard]` → the window, `inventory[title=Cupboard]` → its grid — the widget's own caption would make the most obvious selector anyone writes silently never match), and **`@Class` is an exact `typeName`**, no superclass walk (`@Window` ≠ `CharWnd`); anonymous subclasses are the norm, so `getSimpleName()` would match almost nothing. **The spec's `[res=]` promise was refuted in-game**: NO window on this server carries a resource — of 625 widgets exactly 69 do (62 `WItem`s, the 3 `IMeter`s, and the chat channels whose code ships inside a res) — so `[title=]` is the only key for windows and `[res=]` the correct one for everything item-shaped, and the docs say so instead of keeping the promise; **`:res()` was NOT in the plan** and had to be added, since `[res=]` was otherwise unobservable from Lua. **`hafen.ui.on(sel, "appear"|"disappear", fn)`** hangs off the `onWidgetPlaced` seam and hands back the **Widget entity**, so the thing you wait for is named with the SAME selector you would look it up with and `==` carries state across the two events; **`hafen.ui.onWidgetCreate` and `LuaWidgetObserver` are DELETED** (the `{id,type,place,caption,parentType}` descriptor survives ONLY as `replace{match=fn}`'s argument, which matches against the SERVER parent). **D-068 is the shape that mattered**: registration **scans the live tree** and fires `appear` for what is already open, so "appear" means *is in the tree as of now* — a state reached either way, not an edge — which is why every `:reload` used to lose every open window. **`disappear` fires when a widget stops being *real*, not *drawn***: `UI.destroy` unbinds the id and THEN calls `reqdestroy()`, which `Window` overrides to start a fade-out, so a closing window lingers in the tree, unbound and fully readable, for the whole animation (observed: `exists=true`, `text=Cupboard`) — at `disappear` the entity is a **key to match**, never a last chance to read. Cost scales with widget **creation**, not frames: `Selector` splits into `matchesStructure` (role/class, fixed for a widget's life) + refiners, so only a `[title=]`/`[res=]` selector queues a `PendingMatch`, re-checked **20 ticks** (`-Dhaven.addon.selrecheck=`) — a late-captioned Cupboard fires exactly once. Idle cost is one `isEmpty()` per placement and per tick. **The inspector ships inside the feature**, in `widgetstack` **v0.4.0**: hovering turns into role (or an honest `nil`) · class · `[title=]` · `[res=]`, then **every selector built from those parts that actually matches**, most specific first (role 1 · `@Class` 2 · `[title=]` 4 · `[res=]` 8), each with its match count and this widget's index. **The list is SELF-VALIDATING** — a candidate survives only after `hafen.ui.all()` resolved it and found the widget inside — which forces the honest form (`hafen.ui("…")` only when it is the FIRST match, `hafen.ui.all("…")[i]` otherwise) and absorbs any drift between a Lua re-derivation of a rule and the engine's own. Its in-game surprise: **hovering a window's frame never gives you the window** — the chrome is a CHILD (`@DefaultDeco`, role `nil`), the hit-testing face of "a caption belongs to `Window.Deco`"; `[title=]` still resolves *through* it. Cost 3 walks for a plain widget, 7 with a title, ≤15 for an item, all on a hover **change**; "copyable" = logged (there is no clipboard API in `hafen.*`). **030.4 closed it, docs + Lua only:** the standing **`design/22-ui-selectors.md`** (C, D and E all consume this vocabulary), the sweep of `conventions.md` (**selectors as the third addressing convention** — one string for lookup, listing and waiting), `events.md` (widget appear/disappear are **not on the bus** — you say *which* widget), `fonts.md` (**same names, two consumers**: a scope names a render site, a role a widget), `getting-started.md` (`ui.on` + *don't guess, hover*) and both index tables, with a link/anchor checker over `docs/addons/` reporting **0 broken**; `api/ui.md` itself needed no new section — 030.1–030.3 had each landed their own as they shipped, so the close was the sweep, not the section. `hello` **v0.65.0** gained `readSelectors(tag)` — the once-per-login contract check (login and +3s, plus `:hello selector`): the `*` census, every grammar element with `first == all[1]`, the enclosing-window rule proved on whatever titled window is open, the five site roles all zero, the six parse errors each distinct, an `on()` round trip firing **during** registration with the payload `==` the lookup, and `rootGone`/`onWidgetCreateGone`. Verified before the maintainer's login by **dry-running it against a stub `hafen` bridge under the real LuaJ jar**. **Zero core edits in the whole feature** (two `// addon:` comment texts only). Still deferred deliberately: **`replace(selector, fn)` → B3**, and not for size — `replace` matches a *descriptor* at placement time whose `place`/`parentType` are the SERVER parent (a live `maininv.parent` is already a client-side `Hidewnd`), so a live-tree selector cannot express `context="main"`; converting it is a semantic change. `inventory()`/`equipment()` are NOT cut (they answer "the player's own"; the role answers "every open container").

**NEXT: B3** — the replacement owns the window lifecycle (the client's Tab/menu toggle and a server-opened window resolve to the addon's view; `wndstate` reflects it), which is what stops a custom inventory from merely coexisting beside the stock one. Then C `hafen.ui.skin` → D window chrome over `Window.Deco` → E layout.

**`029-widget-oop` DONE** — **feature B1**: the THREE objects `hafen.ui` handed back for one widget (window/widget handle · `adopt`/`replace` model · transient `WidgetNode`) are ONE interned entity; **what you create and what you find are the same type**, `:info()` the snapshot hatch. The consequence that mattered: **reading stopped being coupled to replacing** — `widget:items()` answers on ANY container with its window **visible and interactive**, where the only previous door was `hafen.ui.adopt(id)`, which HID the native window. **029.1** — the entity + the reads: `LuaWidget` (the addon's own *drawn* widget) → **`AddonWidget`** (package-private; note it now sits beside the unrelated `haven.AddonWidgets`), `LuaWidgetNode` deleted and its role grown into the new **`LuaWidget`** (userdata + per-addon metatable + intern cache, the `LuaMeter` shape with **one deliberate deviation**: the cache is `WeakHashMap<Widget, WeakReference<LuaValue>>`, weak on BOTH axes — **D-064** — because a strong-keyed `IdentityHashMap` over a whole tree would pin every destroyed widget and break D-041; the inner `WeakReference` is load-bearing). `hafen.ui.root()/node(id)/at(x,y)` all hand back that ONE type and the 268-line `nodeHandle` closure-table builder is gone. Reads carried over unchanged **plus `:exists()`/`:info()`**; **`:same()` HARD CUT** — it only existed because nothing was interned, so `widgetstack` collapsed its per-frame hover guard to `if leaf == last then return end` (which also absorbs "still hovering nothing", `nil == nil`). **The measurement gate passed the wrong way round**: per node the OLD `nodeHandle` cost **513 ns** (a `LuaTable` + fifteen closures), an interned hit **27 ns**, a cold insert **201 ns** — one 2000-node walk 1.03 ms → 0.05 ms steady. Interning is ~19x **cheaper** than the handles it replaced; the documented fallback went unused. 029.1 also established that a real `haven.UI` **can** be built off-screen (`bin/builtin-res.jar` for `Text.<clinit>`, an `Unsafe`-allocated `Audio.Root`), recorded in `specs/codebase/boot-and-loop.md`. **029.2** — creation, geometry, and the end of `adopt`: `hafen.ui.window{}`/`widget{}` return the entity, interned on the **ROOT** (the chrome, or the bare widget — `content != root` is the whole "is this a window?" test), so `hafen.ui.at(x,y)` over your own window hands back that very value. Geometry is **arity-as-verb** (`:pos()`/`:size()` read on ANY widget, `:pos(x,y)`/`:size(w,h)` write + chain; `:size(w,h)` resizes the CONTENT then repacks the chrome); `:move()` HARD CUT. **Provenance (OWNED vs BORROWED) is DERIVED from the tree, never stored on the handle (D-065)** — a weak-on-both-axes cache re-mints handles, so a mint-time flag would silently go false under GC; an `AddonWidget` already records its owner + its `root`, so the test is two field reads and is per-addon for free. `:info()` gained **`owned`** (asking beats provoking the error). The write verbs are OWNED-only with two distinct refusals — geometry names **layout, feature E**; `:pack()/:destroy()` names the creation doors — and a write on a STALE widget is a **silent chaining no-op** (a write is not a question). **`adopt` is DELETED** (its whole job was a readable handle, which `hafen.ui.node(id)` now gives with nothing hidden), and with it `model:raw()`; what remains is `w:hide()`, which on a BORROWED widget records the **`Addon.hiddenNative`** restore list — `UiApi.teardownHidden` replays the **ORIGINAL** visibility (hiding something already hidden must not reveal it later), `w:show()` drops its own record, and the relog-vs-`:reload` guard is **two-branch** (`getwidget(id) == wdg` when server-bound, else `hasparent(u.root)` — `w:hide()` can hit a client-only widget, which `replace`'s single id test could not). `replace` itself is untouched except that its builder now returns the entity — the old `view.istable()` check silently yielded null and **leaked the custom view on every undo**. **029.3** — `widget:items()` answers on ANY container (`children(WItem.class)`, a DEEP traversal) with its window visible — proved in-game on an open **Cupboard** (22 items), the `Belt` and the **study**, none of which had an adapter (**D-066**: a thing that lives inside another is a **relation** on it, not a section — so `hafen.items` is a HARD CUT, `inventory()`/`equipment()` became widget LOOKUPS under `hafen.ui`, `hand()` stays a snapshot because the cursor item is not a widget, and `find()` got no replacement: it is a Lua one-liner). Each entry is shaped by its container (an `Equipory` adds `slot`) and the Item SHAPE is unchanged — one `CharApi.itemSnapshot`, so `item.handle` still drives the gated `hafen.act.item` (D-022). The lifecycle moved onto the entity too (`:onItemAdded/:onItemRemoved/:onDestroy`, a per-tick `WItem` diff since an add is a create, not a uimsg) and is **hasSub-gated by construction**: the subscription IS the registration (`Addon.itemWatches`), so an unwatched widget costs one `isEmpty()` and there is no `:watch()`/`:unwatch()` verb; the death test is the same **two-branch** guard; teardown drops the records **without firing** (a `:reload` is not a destroy). That is what let `replace`'s bespoke model handle be **deleted**: `fn(model)` now receives the ENTITY, `LuaModel` is a pure undo record and `pollModels` is destroy-detection only — while `replace`'s own rule is untouched (it hides the enclosing WINDOW; `w:hide()` hides what you point at — `hafen.ui.inventory()` is the GRID, the window is `:parent()`, one hop up, same restore list). **029.4 DONE** — the close, **docs + Lua only, no Java**: `docs/addons/api/ui.md` rewritten around the entity (the ONE type and every door that hands it back incl. `inventory()/equipment()/hand()`; interning + `==` and why there is no `:same()`; staleness; the reads; **owned vs borrowed** as a table of which write answers where; **"Hiding a native widget carries a restore"** as its own heading, with *why there is no `adopt`* under it; `replace` unchanged, now handing over the same entity), **`items.md` DELETED** and folded in as *Items inside a container* + *The container lifecycle*. Swept `types.md` (Item's source), `conventions.md` (`WidgetRef` → a **Widget** reference; Widget joins the OOP roster), `events.md` (container item events are **per-widget, not on the bus** — `EquipChanged` stays global because worn gear is one fixed surface), `fonts.md` (`WidgetNode`/`node:setFont` → Widget, F5 heading + its 3 referrers), `actions.md`, `asset.md`, both index tables and `getting-started.md` (a new *Reading the client's own UI*); a link/anchor checker over `docs/addons/` reports **0 broken**. `hello` **v0.64.0**: `readWidgets(tag)` is the once-per-login contract check (login **and +3s**, plus `:hello widget`) — every door, `node(id)==inventory()`, `at()==at()`, owned/borrowed with **both refusals quoted**, a stale entity (nil reads, `:exists()` false, a write that still chains), the readable containers **with their visibility**, and `itemsGone`/`adoptGone`/`sameGone`/`moveGone`. It builds its **own** throwaway `hafen.ui.widget{}` for the owned half and destroys it in the same call — no ordering dependency, and the corpse is the staleness probe; the container scan **prunes at `Inventory`/`Equipory`** because `:items()` is a deep traversal and calling it per node is O(n²). Verified in-game: three open **Chests** listed with **no `HIDDEN`** marker beside the backpack and the equipory, windows still open and usable; `bags` and `widgetstack` clean. `bags`' manifest lost its one stale "adopts the live inventory as a hidden model" sentence. **Zero core edits in the whole feature; no coverage toll owed.**

**Prior feature:** `028-asset-loader` **DONE** — ONE loader for the files an addon ships: callable `hafen.asset(path)` (D-056) over ONE per-addon intern cache, with the D-017 sandbox resolver in its own home (`AssetApi`). Extension dispatch — `.png/.jpg/.jpeg/.gif/.bmp` image · `.ttf/.otf` font · `.glb/.gltf` mesh (unknown ⇒ an error listing them all). `hafen.asset()` = this addon's **live** assets in load order; `:type()/:path()/:dispose()` on every asset, on top of each type's own verbs (`:size()` · `:derive/:family/:size` · `:bounds()/:info()`). **The loader takes a path and nothing else** (a font's size/style is `:derive{…}`) — so the signature is uniform and `==` never depends on an options table. ## Engine & runtime
- **Engine**: LuaJ embedded (`src/io/brodgar/addon/`); per-addon sandboxed envs (D-017), instruction watchdog + soft per-tick CPU budget with auto-disable (D-018). **Loading/lifecycle**: `manifest.json` discovery from `addons/`; `:reload` rebuilds the addon layer only (D-005); enabled set persisted (D-006). Console `:lua` / `:addons` / `:reload`; AddOns panel (toggle/status).
- **Event bus** `hafen.events.on` (OnLoad/OnEnterWorld/OnUpdate/OnDisable, GobAdded/Removed (a Gob), MeterAdded/Removed/Changed (a Meter), Buff*/Fep/Study/Actionbar/Equip Changed, GhostClicked, ChatMessage…) — error-isolated, UI-thread-marshalled; timers `hafen.timer.after/every`. Container item events are **not** on the bus — they are per-widget (`w:onItemAdded/:onItemRemoved/:onDestroy`, 029.3). **Store**: `hafen.store` JSON saved-vars, per-char + account (D-023).
